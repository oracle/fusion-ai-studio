Best Practices¶

A consolidated checklist for designing, building and running production-grade Agentic Apps.

Design¶

  • Build for decisions, not data. Every section leads with an insight and ends with a path to action (Design Principles).
  • Show the vital few. Keep the Summary View to about 5–7 top-level items at most.
  • Use the five-layer section structure everywhere: headline, description, content, visualizations, footer.
  • Match detail to the view: Summary, then Section Focus, then Item Focus.
  • Use priority tiers consistently across cards, lists and actions.

Architecture¶

  • Match agents to domains. Use specialists for distinct domains; reuse a workflow across panels where the capabilities and data are shared.
  • Use Workflow teams, with Supervisor only as a fallback.
  • One workflow per agent, with a Switch on $OraMessageHint.
  • Pass context explicitly: $inputMessage everywhere it's needed, plus $chatHistory for queries.
  • Match terminal nodes to the output contract: Agent/LLM for generated prose; deterministic Code/Return is suitable for strict JSON.
  • Budget latency. Keep each path well inside the 60-second limit and as few LLM calls as practical.
  • Use a shared communications agent for delivery across the app.

Configuration¶

  • Configure AI Agent Studio before the App Builder.
  • Write capability-rich team descriptions. They drive routing.
  • Select only the widgets an agent needs, and put general widget guidance in the Instructions Prompt.
  • Keep prompt layers separate: house style in AI Agent Studio, app-specific behavior in the Agent Editor.
  • Name the widget and limit the output in every display prompt.
  • State action conditions explicitly and always include payloads in ora.Invoke.
  • Create templates before communications, and keep generation and presentation instructions apart.
  • Forbid invented recipients or content in communication prompts.

Actions¶

  • Keep chains to 2–3 steps; split anything longer than 4–5.
  • Add Refresh Agents after any change to data.
  • Pair Switch App Context with Reload App or Refresh Agents.
  • Use priority: true sparingly.

Testing and release¶

  • Add and preview agents one at a time.
  • Test every configured message hint, including context selection, starter queries, value filters, and capabilities when enabled.
  • Test Ask Oracle in the Summary View and in each Section Focus View.
  • Test communications with real data, not placeholders.
  • Measure latency in Preview.
  • Check the Security Roles before publishing, then monitor usage and iterate. Re-publish to release changes.

Anti-patterns¶

Anti-pattern Why it hurts Instead
One generalist agent with a huge prompt Overloaded context, shallow reasoning, fragile changes Specialist agents per domain
"Display the data" prompts Unpredictable output Name the widget, fields and count
Every item marked critical Nothing stands out Rank by urgency × impact
Insights with no action Users must leave the app Add actions and communications
Assuming context flows automatically Agent "forgets" the question or the history Wire variables explicitly
LLM prose on a strict JSON lookup path Breaks the expected contract Return only the required JSON; use deterministic nodes when appropriate
Duplicating instructions across prompt layers They drift apart and conflict One place for each rule

Additional release checks¶

  • Test shared-workflow panels using their actual display discriminators and widget overrides.
  • Publish backing workflows and verify developer draft badges before publishing the app.
  • Validate the four additional widget types and table multi-selection when used.
  • Check artifact save payloads, including metadata and locked rich-text sections.
  • Run ATLAS workflow and app-panel coverage; resolve pending semantic evaluation and review caveats.
  • Confirm autonomy capabilities use the intended schemas, side-effect flags, and workflow versions.
