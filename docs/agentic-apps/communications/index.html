Communications¶

Communications offer users a send or create flow inside an Agentic App. They can produce an email, text message, presentation, PDF, or podcast. A communication provides the entry point users click; a template, when attached, defines the generated artifact's structure and output format.

Two types of communications¶

App-defined Agent-generated
Configured in Builder UI + Template Editor Agent output at runtime (<oraComms>)
Template Commonly template-backed No template
Formats Determined by the selected template: Email, Text, PowerPoint, PDF, or Podcast Email, Text
Content Template structure; agents fill parameters and sections The agent writes the full content with real data
Best for Structured, recurring output: executive reports, compliance decks, standard notices Ad-hoc, situation-specific messages

Many apps use both: app-defined for reports and agent-generated for contextual outreach.

Formats¶

Format Description Types supported Template sections are…
Email Draft with reviewable recipients, subject, and body App-defined, agent-generated Body sections
Text / Message Text content delivered by the configured target agent App-defined, agent-generated Ordered sections
Podcast Spoken output with configured hosts/voices; availability depends on the builder path Template-backed Host-assigned spoken sections
PowerPoint Slide deck ready to share App-defined only Slides (3 sections = 3 slides)
PDF Document that can be previewed and downloaded in the app App-defined only Sequential document parts (live preview in the editor)

Designing templates¶

Open Browse app components › Document Templates, click Create template, and choose a type. Templates are reusable definitions; create one before selecting it in a communication. When a communication has a templateId, that template usually determines the output type and content shape.

Field Purpose Example
Section Content or Slide Content What to create: data points, analysis, insights "Summarize overall learning compliance: % on track vs. overdue and the top 3 risk areas by department."
Presentation Instructions How to format it "Table with columns Department, Gap Count, Severity. No more than 6 rows."
Auto Fill Section Reveals content instructions for generated PDF/text sections; email also supports static sections —

Keep what and how separate

Put content requests only in generation instructions and formatting rules only in presentation instructions. Mixing them lowers the quality of both.

Add sections or slides in output order. Controls vary by type: email can mix exact static text with generated sections, PowerPoint has presentation types, and podcasts use host, data, and voice settings. See Template Builder for the full controls.

Four-slide PowerPoint template
Slide Generation instructions Presentation instructions
1. Executive Overview Key compliance metrics and overall posture Title + subtitle; key metrics as large numbers
2. Risk Areas Top 3 risk areas with affected learner counts Three-column layout, one risk per column
3. Department Breakdown Compliance by department Two-column comparison
4. Recommended Actions Actions with owners and deadlines Numbered list

Linking a template to a communication¶

flowchart LR
    T[1 · Create template<br/><small>Template Editor</small>] --> C[2 · Create communication<br/><small>Builder › Communications</small>]
    C --> A[3 · Enable on agents<br/><small>Include in Communications</small>]

Step 1 — Create the template (see above).

Step 2 — Create the communication. In the Builder's Communications panel, click Add Communication:

Field Description
Title Name shown in the communications panel, e.g. "Learning Compliance & Risk Summary"
Description When to suggest it. Agents use this to judge relevance.
Applicable Agents Which agents may suggest it (choose at least one); use real configured agent codes
Template The template from step 1. The dropdown is empty until a template exists.
Action Text (Email/Text) Button label, e.g. "Send Email", "Alert Team"
Target Agent (Email/Text) Agent that delivers it. Required for Text; must be the exact agent code.

Step 3 — Enable on agents. Tick Include in Communications? in each applicable agent's Agent Editor. If this is not ticked, the agent won't suggest the communication even when it is listed as applicable.

Deleting templates

Deleting an app-local template clears local communication references to it. Check dependencies first.

Communication lifecycle¶

Template-backed generation can include parameter filling before creating the output. Agent-generated drafts already contain their message body and use parameters for values the user should review or edit. Follow the path appropriate to the communication type:

sequenceDiagram
    autonumber
    participant A as Domain agent
    participant App as Agentic App
    actor U as User
    participant D as Delivering agent
    A->>App: Suggest (InitCommunications or in a response) + prefill known params
    U->>App: Selects communication
    opt Template flow needs parameter filling
        App->>A: FillParameters (params-to-fill array)
        A-->>App: Remaining values
    end
    App->>U: Review draft or generation settings
    U->>App: Confirm send or create
    alt Delivery workflow configured
        App->>D: SendCommunication
        D-->>U: Delivery result
    else Artifact generation
        App-->>U: Generated output for review or download
    end
Stage What happens
1. Suggest Agents propose communications at startup (InitCommunications) or in responses. App-defined ones are matched on their Description.
2. Prefill The agent fills parameters it already knows (supplier name, value, dates).
3. Fill parameters when needed Template flows can use FillParameters to complete missing values. Generated messages should already have their body in content.
4. User review The user reviews the communication and edits available send-time fields or cancels. Email recipient, CC, and subject are editable.
5. Send or create The configured flow delivers the message or generates the artifact. Delivery workflows handle SendCommunication and can use $OraCommNonTemplateParamList when supplied.

Two ways communications are triggered¶

  • General communications: set up at app level and suggested by any applicable agent.
  • Communication-triggering actions: tied to a specific high-priority item, with the message tailored to that record.

Agent-generated communications: <oraComms>¶

Return an <oraComms> element containing raw JSON. In actual workflow output, omit Markdown code fences. Agent-generated suggestions use type: "email" or type: "text" and do not attach a template. Supply the completed body in content; do not depend on another agent to write it later.

<oraComms>
{
  "type": "email",
  "title": "Notify AcmeParts of Renewal Terms",
  "shortDescription": "Contract ACME-2024-001 expires Nov 14; proposes 5% volume discount.",
  "actionText": "Send Email",
  "targetAgent": "SUPPLIER_COMMS_AGENT",
  "content": "Hello Dana,\n\nYour supply agreement ACME-2024-001 expires on November 14, 2026. Based on 18 months of volume, we propose renewing at current terms with a 5% volume discount...",
  "params": [
    { "id": "email", "title": "Recipient", "defaultValue": "dana.lee@acmeparts.example" },
    { "id": "subject", "title": "Subject", "defaultValue": "Renewal of agreement ACME-2024-001" }
  ]
}
</oraComms>
Field Description
type email or text
title Name shown in the communications panel
shortDescription When or why this communication applies
actionText Button label
content The actual message body, with real data and no placeholders
params[] Values the user can review or edit: id, title, optional description, defaultValue, and editable. Email fields use email, cc, and subject. Describe each value precisely; multiple email recipients can be comma-separated.
targetAgent Exact code of the delivery workflow; supply it for both text and email

Golden rule: never fabricate

Tell agents never to invent recipients, email addresses or content. If a value is unknown, leave defaultValue empty so the user fills it in during review.

Agent-generated communications require Enable Communications for the widgets on the node's App Experience section.

If the node also generates widgets, select their types under Select the widgets you want to use. Use Instructions for guidance shared across the node's communication and display output.

Text communication with a reviewable audience
<oraComms>
{
  "type": "text",
  "title": "Share Delivery Review",
  "shortDescription": "A delivery review is ready for the operations team.",
  "actionText": "Send Review",
  "targetAgent": "OPERATIONS_DELIVERY_AGENT",
  "content": "Delivery review: Two shipments require revised arrival estimates. Confirm the updated dates with their owners before notifying customers.",
  "params": [
    {
      "id": "audience",
      "title": "Audience",
      "description": "Team that should receive the delivery review.",
      "defaultValue": "Operations",
      "editable": true
    }
  ]
}
</oraComms>

Use this shape with facts retrieved for the current request and the exact code of an existing delivery workflow.

Prompt patterns¶

App-defined: when to suggest
Suggest the "Executive Summary" communication when the user is in the Summary View.
Suggest "Send Risk Alert" when any compliance item is overdue by more than 14 days.
Agent-generated: what to write
When a supplier contract expires within 7 days, generate an email oraComms to the
supplier's primary contact. Include contract ID, renewal terms and expiry date in the body.
Use the email address from the contract record. Do not fabricate any recipient information.

Common mistakes¶

Mistake Fix
Template dropdown is empty Create the template first
Generation and presentation instructions mixed together Separate what from how
One section covering five topics Split it into several sections
Tested only with placeholder data Test with the real agents that will fill the template
Enable Communications off Turn it on in the App Experience section
Include in Communications? unticked Tick it in the Agent Editor
No applicable agents Assign at least one
Text communication without a target agent Set Target Agent / targetAgent
Fabricated content Forbid it explicitly in the prompt

Current placement and sharing behavior¶

Static template-backed communications appear in the communications area. Agent suggestions gathered during startup communication collection appear in Priority Actions. When generated alongside InitDisplay, high-priority suggestions appear there and lower-priority suggestions stay inline with the agent content.

Share a chat response¶

  1. Select Share panel in the chat response panel's upper-right toolbar.
  2. Choose a communication channel and review the content.
  3. Select Share in the communication panel.

Email is provided by default. In App Settings, developers can configure email or add custom channels. For a custom channel, select the handling agent and content format; the default format is plain text.

When the user selects Share, the handler receives SendCommunication and reads the shared content from $context.$system.$inputMessage. It may return confirmation or throw an error on failure.

Podcast is a supported template type, while some builder tooling focuses on email, text, PowerPoint, and PDF. Use the selected template to confirm the communication's actual output type.
