Anatomy of an Agentic App¶

Every Agentic App is made of one or more agent teams built in AI Agent Studio. Those agents fill the app through four dynamic core areas, inside a consistent page and section structure, driven by a defined lifecycle. This page describes each of those parts.

The four areas¶

1. Ask Oracle - Advisors¶

Ask Oracle is the conversational layer: a persistent bar where users ask questions in natural language and get answers from the app's specialist agents. Answers combine text with full information displays.

  • Chat panel as memory. Opening the Ask Oracle bar shows a panel that keeps the session's prompts, uploaded files, generated artifacts, cited sources and suggested actions.
  • Response placement. A response appears as a new section at the top of the page.
  • Pinning. By default a new response replaces the previous one. Sections the user pins are kept, and new responses appear above them.
  • Scoping. In Section Focus View, Ask Oracle talks only to the agents behind that section.

See Ask Oracle Advisors.

2. Information Displays¶

Information displays are the visual backbone of the app. The UI is not hard-coded. Agents emit structured display metadata, and the framework renders it as interactive widgets.

Aspect Behavior
Generation Agents emit an <oraInfoDisplay> block containing a title, a widget type (patternId), a description and widget properties. See Output Tags.
Hosting Each agent's output appears in its assigned slot in the page layout. The page template controls rendering and dismissal.
Context awareness Each display carries a topic key. When the conversation moves on, the template can hide displays that are no longer relevant.
Startup Every agent is asked for its initial displays through the InitDisplay message hint, so the app never opens empty.
Default response Agents built for apps answer with displays by default. Plain text is reserved for clarifications, confirmations and very short replies.

Agentic Apps support eleven widget types: Chart, Card, Message List, Change List, Multi Record, Record, Sankey, Multi Card, Artifact Preview, Comparison, and Toggle Bar. See Information Display Widgets.

3. Actionable Insights¶

An actionable insight is a self-contained decision point that an agent produces when something needs a human decision.

Component Description Example
Title Short label shown in the Actions panel "Renew AcmeParts Contract"
Description Why it matters "Expires in 3 days; renewal with 5% volume discount saves $47K/yr"
Execution instructions The command the agent runs when the user clicks. Generated by the agent; the user can't edit it. ora.Invoke("renewContract", "ACME-2024-001")

Key behaviors:

  • Single-agent ownership. The agent that created an action also executes it when the user clicks.
  • Produced at startup and at runtime. Actions appear at startup (InitActions), in answers to queries, and inside widgets (row actions, card links).
  • Instant or workflow. One click, or a multi-step flow defined in the Actions Editor.
  • Can trigger communications. An action can produce a tailored message about the same record.

See Actions.

4. Communications¶

Communications handle outbound follow-through, so users don't have to switch to email, chat or slide tools.

Type Configured in Formats Content
App-defined Builder UI + Template Editor Email, Text, PowerPoint, PDF Template structure; agents fill the parameters
Agent-generated Agent output (<oraComms>) at runtime Email, Text Agent writes the real content; no placeholders

Note

Communications are always outbound. They never intercept incoming messages. Delivery can be routed to any agent, including one shared, reusable communications agent.

See Communications.

The three views¶

An Agentic App presents information at three levels of depth:

View Purpose Ask Oracle scope
Summary View Top-level entry point: a short overview of what needs attention now All relevant agents
Section Focus View One section expanded with more items and richer detail Only that section's agents
Item Focus View Deep dive into one record, with full context and dedicated insights That item's context 
flowchart LR
    S[Summary View<br/><small>vital few items</small>] -->|drill into section| F[Section Focus View<br/><small>full prioritized list</small>]
    F -->|open a record| I[Item Focus View<br/><small>history, related records, analysis</small>]

Standard section structure¶

Each section follows the same five layers, so users learn the layout once and recognize it everywhere:

Layer Content Example
1. Headline The single most important finding "3 supplier contracts expire this week"
2. Short description Why it matters, what triggered it, scope "Two are high-value; AcmeParts carries the highest SLA risk"
3. Content Detail rendered through one or more widgets Message list of the 3 contracts with priority badges
4. Visualizations Charts and diagrams for trend, comparison or flow Line chart of AcmeParts on-time delivery
5. Footer Sources (to verify) and suggested actions (to act) "Source: Supplier contracts" · Review & Renew

Page layout and slots¶

Agents are placed in slots in a page layout (single-column, two-column or asymmetric), configured under Page Options in the Builder UI. The recommended pattern is one agent per panel. Two special app-level slots sit above the layout:

  • Ask Oracle: optional dedicated agent for user queries
  • Summary: optional dedicated agent for the top summary

If you leave those slots empty, the Agentic App Orchestrator builds the summary and routes queries across your panel agents. See Builder UI › Static agents.

An agent can also have additional panels: named sections that load below its main content when the user focuses on it. See Configure Agents › Panels.

Putting it together: a typical session¶

sequenceDiagram
    autonumber
    actor U as User
    participant App as Agentic App
    participant P as Procurement agent
    participant C as Comms agent
    U->>App: Opens app
    App->>P: Summary / InitDisplay / InitActions / InitCommunications (parallel)
    P-->>App: Summary line, message list, "Renew AcmeParts" action
    U->>App: Drills into Procurement (Section Focus)
    U->>App: Ask Oracle: "Which contract is riskiest?"
    App->>P: Query
    P-->>App: Card widget + action
    U->>App: Clicks "Review & Renew"
    App->>P: InvokeAction ($OraAction = contract ID)
    P-->>App: Confirmation + suggested supplier email
    U->>App: Reviews and sends email
    App->>C: FillParameters → SendCommunication
    App->>P: Refresh display (status resolved)

The four pillars work as one system. Displays show what matters, actions let users decide, communications let them follow through, and Ask Oracle lets them explore.
