App Settings¶

App Settings controls the app's header, access, response behavior, and context selection. Open the app in Builder view and select Open property panel next to the title to display App Settings.

Settings follow the panel labels, including additional controls available in Release 26D.

Name¶

Edits the application name.

Description¶

Edits the application description.

Title¶

Sets the app's display name in the header and app catalog. Use a short, descriptive name that identifies the workspace.

See Configure app settings.

Subtitle¶

Sets an optional static tagline beneath the title. Use it to give users a brief description of the workspace or its scope.

See Configure app settings.

Dynamic Title and Subtitle Agent¶

In Release 26D, Dynamic Title and Subtitle Agent handles InitTitle and InitSubtitle; generated values override the static fields.

The same setting is described elsewhere as Dynamic Title and Subtitle Agent. See Dynamic Title and Subtitle Agent for configuration.

Security Roles¶

Users need access to the application and each backing workflow. If workflow access is missing, its application section is unavailable. Check role assignments on both the application and its workflows before publishing.

See Configure app settings and Publish.

Enable autonomous outcomes¶

Reveals Autonomous Outcomes for autonomy configuration.

See Enable and configure.

Initially hide actions panel when empty¶

Hides the actions panel initially when it has no content. Users can still reveal the panel. This can help keep an advisory workspace focused when there are no actions to show.

See Configure app settings. For how agents populate actions, see How agents produce actions.

Initially hide agent panel when empty¶

Initially hides the agent panel when no agents are configured.

Prefer single priority actions¶

Initially shows the highest-priority action. Select View more for the others.

See Priority actions.

Automatically translate agent responses¶

Uses the workflows' language settings. Configure Answer in user's language in workflow Settings → Chat Experience, or on individual LLM and Agent nodes. Language instructions can also be supplied in prompts.

See Configure app settings.

Enable file upload¶

Allows file uploads. Configure a Chat Attachments Reader Tool node (also called Multifile Processor) to process them. Its Parse Files option extracts readable content; Make Raw File Content Available (in base64 format) supplies original bytes for downstream handling.

See Attachment context.

Enable email attachments¶

Allows users to attach files to email communications.

See Communications

Enable Context Switching¶

Enables a selection view where users choose the record or business scope before opening the workspace. The backing workflow supplies initial choices, handles searches, and can optionally return a default context.

The configuration is also labeled Enable app context switching. When enabled, configure Agent and Search Placeholder under App Context Switching. Selected context is available to app workflows as $context.$app.$OraAppContext.

See Configure the switcher in App Settings and Workflow request and response contract.

Context Switching¶

Configure these fields after enabling context switching:

Setting Details
Agent Select the workflow that returns context choices. It handles InitContextSuggestions for initial choices and QueryContextSuggestions for searches.
Search Placeholder Set the prompt shown in the context search field, such as Select a supplier.

See Configure the switcher in App Settings for setup and Workflow request and response contract for the expected output and optional default context.

Share Response Channels¶

Configure the channels users can choose when sharing a chat response through Share panel. Email is available by default; custom channels use a handling agent and a selected content format.

Control Details
Email Configure recipients for the default email channel.
Existing channel, such as New Channel Opens that channel's configuration. For a custom channel, select the agent that handles shared content and its content format; plain text is the default.
+ Add Channel Adds a custom response-sharing channel.

Custom-channel fields:

Field Purpose
Label Sharing option name
Response Agent Delivery workflow; enable its action and communication widgets
Response Format Plain Text or HTML, matching agent support

When a user confirms Share, the handling workflow receives SendCommunication. Shared content is available in $context.$system.$inputMessage; the workflow can return a confirmation or throw an error if delivery fails.

See Share a chat response for the user flow and handling behavior.

Page Options¶

Select the column layout for agent panels. The four icons, from left to right, represent:

Layout Arrangement
Single column One full-width column
Two equal columns Two columns of equal width
Wider left column Two columns with more space on the left
Wider right column Two columns with more space on the right

Agents occupy slots within the chosen layout. See Page layout and slots and Configure app settings.
