Information Display Widgets¶

Widgets are the visual building blocks of Information Displays. An agent emits an <oraInfoDisplay> block. Its patternId tells the framework which widget to render, and its properties object holds the widget's data.

Display envelope¶

Every display uses the same envelope:

{
  "title": "Display title shown to the user",
  "patternId": "chartWidget | cardWidget | messageListWidget | changeListWidget | multiRecordWidget | recordWidget | sankeyWidget | multiCardWidget | artifactPreviewWidget | comparisonWidget | toggleBarWidget",
  "description": "Short description of what is shown",
  "properties": { }
}
Field Description
title Heading shown to the user
patternId Which widget to render
description Short explanation of the display
properties Widget-specific data (see each widget below)

The <oraInfoDisplay> tag also takes a key attribute identifying the display. Use a stable descriptive value, such as supplier-risk-chart. See Output Tags.

Prerequisite

An agent can only render the widgets selected under Select the widgets you want to use in its node's App Experience section. If no widget is selected, <oraInfoDisplay> output is silently ignored. See Configure Agents.

The Builder's display prompt describes what the agent should produce; the agent's output supplies the widget JSON. Keep any explicit displayWidgetList restriction aligned with the widgets requested in that prompt. Use the node's Instructions field for shared widget guidance.

Interactive commands¶

Use ora.Invoke("actionCode", payload) for new widget interactions backed by app-defined actions. Action fields contain executable command strings, not bare action identifiers. Direct commands such as ora.Agent(...) and ora.App.launch(...) remain available for existing flows.

To create an Autonomous Outcomes plan preview, use ora.InvokeAsync({"mode":"Research"}, "task text"). The first argument is strict JSON; supported modes are Quick, Research, Act, and Full Auto.

An item action can open a communication with ora.SendComm("inlineActionId"), matching the communication's inlineActionId. When an app action changes visible data, include a refreshAgents step to update the affected panels. See Actions for command and refresh configuration.

Widget catalog¶

Widget patternId Best for
Chart chartWidget Trends over time (line), category comparisons (bar), proportions (pie)
Card cardWidget One alert or status with a severity level
Message List messageListWidget Prioritized lists of alerts, messages or pending items
Change List changeListWidget Current vs. previous KPI comparisons
Multi Record multiRecordWidget Tables with badge cells and row actions
Record recordWidget Single-record details or editable forms
Sankey sankeyWidget Flows of quantity between stages
Multi Card multiCardWidget Several peer status cards
Artifact Preview artifactPreviewWidget Inline previews that open artifact viewers/editors
Comparison comparisonWidget Option details and side-by-side comparisons
Toggle Bar toggleBarWidget Select one related view at a time

Chart widget¶

Line, bar or pie charts. Multiple datasets can be overlaid. Axes, legends and data points are rendered for you.

{
  "title": "Overdue Receivables Trend",
  "patternId": "chartWidget",
  "description": "Overdue balance (USD) for the last 6 months",
  "properties": {
    "type": "line",
    "data": {
      "labels": ["May", "Jun", "Jul", "Aug", "Sep", "Oct"],
      "datasets": [
        { "label": "Overdue > 30 days", "data": [410000, 455000, 430000, 520000, 610000, 847000] },
        { "label": "Overdue > 90 days", "data": [90000, 95000, 88000, 120000, 160000, 240000] }
      ]
    },
    "insights": [
      "90+ day balance has grown 2.7x since May",
      "October jump driven by two enterprise accounts"
    ]
  }
}
Property Required Type Description
type Yes String line (time series), bar (comparison) or pie (proportion)
data.labels Yes String[] X-axis labels, or slice names for pie
data.datasets Yes Object[] One or more series
data.datasets[].label Yes String Series name (legend)
data.datasets[].data Yes Number[] Values. Length must equal labels length.
insights No String[] 1–3 takeaways shown under the chart. Point out anomalies rather than repeating the numbers.
referenceObjects No Object[] Threshold lines or range areas for line and bar charts; ignored for pie charts

Keep measured series in data.datasets. Put targets, thresholds, and acceptable ranges in referenceObjects instead. A number sets a constant reference; arrays provide one value per label and must match data.labels.length.

Reference objects inside properties
{
  "referenceObjects": [
    {"type":"line","label":"Target","value":500},
    {"type":"area","label":"Expected range","yMin":[400,450,500],"yMax":[550,600,650]}
  ]
}

The range example assumes three labels.

Pitfalls

If the data and labels lengths differ, the chart renders incorrectly. Keep pie charts to 5–7 slices.

Card widget¶

One important alert or notification. For several items, use a Message List.

{
  "title": "Contract Expiry",
  "patternId": "cardWidget",
  "description": "Highest-risk supplier contract",
  "properties": {
    "subject": "AcmeParts Contract Expiring",
    "summary": "Expires in 3 days; on-time delivery fell 40% in 6 months.",
    "timestamp": "Today",
    "badgeText": "CRITICAL",
    "variant": "error",
    "link": {
      "text": "Review & Renew",
      "action": "ora.Invoke(\"reviewContract\", \"ACME-2024-001\")"
    }
  }
}
Property Required Type Description
subject Yes String 2–6 words, Title Case
summary Yes String 1–2 sentences, under ~100 characters: what happened and why it matters
timestamp No String Relative time, e.g. "5 min ago"
subtitle No String Secondary context below the subject
image No String Image URL, rendered as a 72px square thumbnail on the right
status No String Status text
statusPriority No String Status color: alert, warning, medium, success, or neutral
badgeText No String ALL CAPS label, e.g. CRITICAL, HIGH, INFO
variant No String error (red), warning (orange), info (blue), success (green), neutral (gray); omitted or null is neutral
link.text No String Button label
link.action No String Command to run on click: ora.Invoke(), ora.Agent() or ora.App.*()
additionalLink No Object Second link with text and an action command string

variant controls badge color; statusPriority controls status text color. The thumbnail aligns with the first available line among subject, subtitle, summary, and status.

Message List widget¶

A scrollable, prioritized list where each item can have a badge, a timestamp and a click action. Use it for notification queues and pending-item lists.

{
  "title": "Overdue Certifications",
  "patternId": "messageListWidget",
  "description": "Employees with lapsed mandatory training",
  "properties": {
    "subtitle": "EMEA Operations",
    "items": [
      {
        "title": "Data Privacy Training — J. Ortiz",
        "summary": "Overdue by 21 days; blocks system access renewal on Nov 30.",
        "badgeText": "HIGH",
        "priority": "alert",
        "timestamp": "21 days overdue",
        "action": "ora.Invoke(\"assignTraining\", \"{\\\"personId\\\":\\\"300100\\\",\\\"course\\\":\\\"DP-101\\\"}\")"
      },
      {
        "title": "Fire Safety Refresher — 4 employees",
        "priority": "warning",
        "timestamp": "Due in 5 days"
      }
    ]
  }
}
Property Required Type Description
subtitle No String Context for the list
items[].title Yes String Main heading of the item
items[].subtitle No String Secondary context (category, confidence)
items[].summary No String Details with specific metrics
items[].status No String Status text for the item
items[].statusPriority No String Same values as priority; use when the status needs a different color from the badge
items[].badgeText No String ALL CAPS label
items[].priority No String alert (red), warning (orange), medium (informational blue), success (green), neutral (gray)
items[].timestamp No String Relative time
items[].action No String Makes the item clickable, e.g. ora.Invoke("name", "context")
items[].image No String Avatar/icon URL (shown at 48px)
items[].additionalAction No Object Secondary action with text and command; visible only in a focused panel

Tip

Use alert priority only for genuinely critical items. If there is just one item, use a Card instead.

Change List widget¶

KPIs with current and previous values. Direction arrows and percentage change are added automatically.

{
  "title": "Collections KPIs",
  "patternId": "changeListWidget",
  "description": "October vs. September",
  "properties": {
    "displayType": "percentage",
    "subtitle": "Oct vs Sep",
    "items": [
      { "title": "Collection Effectiveness Index", "currentValue": 82.4, "previousValue": 86.1 },
      { "title": "Dispute Rate", "currentValue": 3.1, "previousValue": 2.2 }
    ],
    "messages": ["Dispute rate rise concentrated in two retail accounts — review pricing disputes first"]
  }
}
Property Required Type Description
displayType Yes String percentage, raw or currency
items[].title Yes String Metric name
items[].currentValue Yes Number Latest value. Numbers only, with no % or $.
items[].previousValue Yes Number Baseline value. Numbers only.
subtitle No String Header context, e.g. "Q4 vs Q3"
messages No String[] Actionable analysis of anomalies

Multi Record widget¶

A table with columns, badge-style status cells and optional row actions.

{
  "title": "Invoices Awaiting Approval",
  "patternId": "multiRecordWidget",
  "description": "Invoices above approval threshold",
  "properties": {
    "subtitle": "Sorted by amount",
    "cols": ["Invoice", "Supplier", "Amount", "Status"],
    "rows": [
      {
        "cells": ["INV-88213", "Northwind Metals", "$184,200",
                  { "type": "badge", "text": "ON HOLD", "priority": "warning" }],
        "action": { "text": "Review", "command": "ora.Invoke(\"reviewInvoice\", \"INV-88213\")" }
      },
      {
        "cells": ["INV-88190", "Contoso Freight", "$92,750",
                  { "type": "badge", "text": "READY", "priority": "success" }]
      }
    ]
  }
}
Property Required Type Description
cols Yes (String | Object)[] Column headers; objects use label and optional showOnExpand
rows Yes Object[] Row objects
rows[].cells Yes (String | Badge)[] One entry per column. Count must match cols.
Badge cell — Object {"type":"badge","text":"ACTIVE","priority":"success"}
rows[].action No Object {"text":"View","command":"ora.Invoke(...)"}
rows[].drillDownAction No String Command invoked from the first column
subtitle No String Table description (accessibility)

Columns marked showOnExpand: true appear only when the widget is focused. For example, {"label":"Owner","showOnExpand":true} keeps secondary information out of the compact table.

For checkbox selection, set selectMode: "multiSelect" and provide an id. Use multiSelectActionText to replace the default Submit label and multiSelectMetadata to carry routing context into the submission. See Multi-select table submit for the returned payload.

Badge priority values: alert (red), warning (orange), medium (informational blue), success (green), neutral (gray).

Record widget¶

One record shown as typed fields, either read-only or as an editable form.

{
  "title": "Adjust Credit Limit",
  "patternId": "recordWidget",
  "description": "Proposed credit limit change",
  "properties": {
    "id": "credit_limit_form",
    "readOnly": false,
    "fields": [
      { "id": "customer_name", "type": "text", "label": "Customer", "value": "Blue Yonder Retail" },
      { "id": "new_limit", "type": "number", "label": "New Limit (USD)", "value": 250000 },
      { "id": "effective_date", "type": "date", "label": "Effective Date", "value": "2026-12-01" },
      { "id": "reason", "type": "select", "label": "Reason", "value": "risk",
        "options": [ { "value": "risk", "label": "Risk Reduction" }, { "value": "growth", "label": "Growth" } ] },
      { "id": "notes", "type": "textarea", "label": "Notes", "value": "" }
    ]
  }
}
Property Required Type Description
id Yes String Form identifier, returned in <oraFormSubmit>
readOnly No Boolean true = display only; false = editable (default false)
submitText No String Editable form button label; defaults to Submit
fields[].id Yes String Field identifier (snake_case)
fields[].type Yes String text, textarea, number, date, select, or system
fields[].label When applicable String Visible field label; system fields can omit it
fields[].value Yes Varies Initial value
fields[].options Conditional Object[] {value, label} pairs. Required for select when editable.

When readOnly is false, a Submit button appears. On submit, the app sends <oraFormSubmit id="credit_limit_form"> with the field values as JSON for your agent to process.

Submission uses ora.Agent(<oraFormSubmit ...>) automatically; the widget needs no separate submit command. A system field can carry a structured value and can omit its label.

Read the envelope from $context.$system.$inputMessage. Route by the submitted form ID before interpreting its JSON; record forms and artifact editor saves use the same envelope with different payload shapes.

Extract a form submission (illustrative Code node)
const input = $context.$system.$inputMessage || "";
const match = input.match(
  /<oraFormSubmit\s+id=["']([^"']*)["'][^>]*>([\s\S]*?)<\/oraFormSubmit>/
);

if (!match) return { isFormSubmit: false };

try {
  return { isFormSubmit: true, formId: match[1], payload: JSON.parse(match[2]) };
} catch (e) {
  return { isFormSubmit: true, formId: match[1], error: "Invalid form JSON" };
}

Pass the parsed result to the appropriate handler. For editor saves, consume newValue and metadata as described in Artifact editing. Adapt Code node return conventions to your release.

Sankey widget¶

A flow diagram in which link width is proportional to quantity. Nodes are arranged left to right and colored automatically.

{
  "title": "Service Ticket Routing",
  "patternId": "sankeyWidget",
  "description": "How October tickets were resolved",
  "properties": {
    "nodes": [
      { "id": 0, "name": "New Tickets" },
      { "id": 1, "name": "Self-Service" },
      { "id": 2, "name": "Tier 1" },
      { "id": 3, "name": "Escalated" },
      { "id": 4, "name": "Resolved" }
    ],
    "edges": [
      { "source": 0, "target": 1, "value": 420 },
      { "source": 0, "target": 2, "value": 580 },
      { "source": 2, "target": 3, "value": 95 },
      { "source": 1, "target": 4, "value": 400 },
      { "source": 2, "target": 4, "value": 485 },
      { "source": 3, "target": 4, "value": 80 }
    ]
  }
}
Property Required Type Description
nodes[].id Yes Number Unique numeric ID
nodes[].name Yes String Node label
edges[].source Yes Number Source node ID (must exist)
edges[].target Yes Number Target node ID (must exist)
edges[].value Yes Number Positive flow quantity, which sets the link width

Nodes with no incoming edges become sources (far left). Nodes with no outgoing edges become sinks (far right).

Multi Card widget¶

Use multiCardWidget for several peer cards. Required properties.cards[] entries use the Card schema: subject, summary, and optional subtitle, image, status, statusPriority, timestamp, badgeText, variant, link, and additionalLink.

{
  "patternId": "multiCardWidget",
  "properties": {
    "cards": [
      {"subject":"Delivery","summary":"Two shipments need review.","variant":"warning"},
      {"subject":"Contracts","summary":"No contracts expire this week.","variant":"success"}
    ]
  }
}

Optional layoutMode accepts default, collapsed (compact two-column layout), or single-col. Omit it unless a specific layout is needed.

Artifact Preview widget¶

Use artifactPreviewWidget for content that users should review or edit in the artifact sidebar. Each entry in required properties.items[] needs artifactId, title, mode, and content. Modes are preview, edit, and custom. Only custom items use an explicit action; preview/edit open the viewer directly.

{
  "patternId": "artifactPreviewWidget",
  "properties": {
    "items": [
      {
        "artifactId": "supplier-review-draft",
        "title": "Supplier review draft",
        "mode": "edit",
        "content": {
          "id": "supplier_review",
          "type": "text",
          "value": "Review the delivery evidence before contacting the supplier.",
          "commitText": "Save",
          "metadata": {"supplierId":"SUP-1042"}
        }
      }
    ]
  }
}

Content follows the artifact editor payload. Text and rich text use value; structured rich text uses sections[] with name, locked, and text. PDF and URL content remain read-only even with mode: "edit".

Items can also set subtitle and actionText. For URL content, set content.type: "url" and content.url; the card and viewer display it in an iframe without submitting an edited value. Structured rich text keeps locked sections visible while preventing edits to them.

Saving sends oraFormSubmit with newValue and metadata, including metadata.artifactId from the preview item. The matching preview card updates in place. The workflow must consume the submit payload rather than rely on the UI state.

The submit ID is content.id, falling back to artifact when absent. newValue is a string for text and rich text, or the updated sections array for structured rich text.

Comparison widget¶

Use comparisonWidget to compare named alternatives with individual tabs and a compare tab. Required sections[] define keys; required items[] define options and values.

{
  "patternId": "comparisonWidget",
  "properties": {
    "sections": [{"id":"terms","keys":[{"id":"term","label":"Term"}]}],
    "items": [
      {"id":"annual","name":"Annual","title":"One-year renewal","values":[{"keyId":"term","value":"12 months"}]},
      {"id":"quarterly","name":"Quarterly","title":"Quarterly renewal","values":[{"keyId":"term","value":"3 months"}]}
    ]
  }
}

Keys require id and label. Items require id, name, title, and values[]. Include sectionId for later sections or repeated key IDs. Values can be scalar JSON values, yes/no status cells such as {"status":"yes"}, or an object with focused and comparison overrides.

Optional actionTemplate creates a button per option. Its tokens are {id}, {name}, and {title}; use stable {id} in command payloads. Optional statusText.status accepts alert, warning, medium, success, or neutral.

Sections can set title, keyHeader, and valueHeader; their id is optional for the first section. Items can add subtitle, description, and statusText: {"text":"Recommended","status":"success"}. Top-level showRecommended and descriptionLabel customize the presentation.

Optional actionTemplate inside properties
{
  "actionTemplate": {
    "text": "Select {name}",
    "command": "ora.Invoke(\"selectOption\", {\"optionId\":\"{id}\"})",
    "contextualText": "Select {name}: {title}"
  }
}

Template token names stay the same across locales. A value such as {"focused":"Included in this option","comparison":{"status":"yes"}} gives the detail tab explanatory text and the comparison tab a status icon.

Toggle Bar widget¶

Use toggleBarWidget to show one of at least two related views. Each required option has id, label, and content; content.widget has exactly patternId and properties.

{
  "patternId": "toggleBarWidget",
  "properties": {
    "selectedOptionId": "delivery",
    "options": [
      {
        "id":"delivery","label":"Delivery",
        "content":{"title":"Delivery status","widget":{"patternId":"cardWidget","properties":{"subject":"Delivery","summary":"Review delayed shipments."}}}
      },
      {
        "id":"contracts","label":"Contracts",
        "content":{"title":"Contract status","widget":{"patternId":"cardWidget","properties":{"subject":"Contracts","summary":"Review approaching renewals."}}}
      }
    ]
  }
}

Put view titles and descriptions on content, outside the nested widget. Supported children are the catalog's other widget types except Comparison and Toggle Bar. Do not nest comparisonWidget or another toggleBarWidget. Use content.actionButton for a primary action and content.suggestedActions[] for additional actions. Optional subtitle labels the toggle group for accessibility.

Each option owns one nested widget. Optional content.tertiaryText adds context and content.statusMessage supplies text and status. Action buttons and suggested actions use text, an action command string, and optional contextualText:

Optional fields inside an option's content
{
  "statusMessage": {"text":"Review required","status":"warning"},
  "actionButton": {
    "text":"Review",
    "action":"ora.Invoke(\"reviewSelection\")",
    "contextualText":"Review the selected view"
  },
  "suggestedActions": [
    {"text":"Assign owner","action":"ora.Invoke(\"assignOwner\")"}
  ]
}

Use separate widgets when users need to see all views at once.

Widget selection guide¶

flowchart TD
    Q{What is the data story?}
    Q -->|Trend over time| L[chartWidget · line]
    Q -->|Compare categories| B[chartWidget · bar]
    Q -->|Share of a whole| P[chartWidget · pie]
    Q -->|One urgent alert| C[cardWidget]
    Q -->|Several prioritized items| M[messageListWidget]
    Q -->|Before vs. after KPIs| CH[changeListWidget]
    Q -->|Many records, same columns| T[multiRecordWidget]
    Q -->|One record or a form| R[recordWidget]
    Q -->|Flow between stages| S[sankeyWidget]
    Q -->|Peer status cards| MC[multiCardWidget]
    Q -->|Review an artifact| AP[artifactPreviewWidget]
    Q -->|Compare alternatives| CO[comparisonWidget]
    Q -->|Switch related views| TO[toggleBarWidget]

Example display prompt¶

- Show critical alerts with cardWidget, variant "error".
- Show lists of notifications with messageListWidget and the right priority levels.
- Show period comparisons with changeListWidget, displayType "percentage".
- Show tabular data with multiRecordWidget; use badge cells for status columns.
- Use chartWidget type "line" for time-series trends.
- Never use messageListWidget for a single item. Use cardWidget instead.

Common mistakes¶

Mistake Fix
No widgets selected in the App Experience section Select at least one; otherwise displays are silently dropped
Array length mismatch datasets[].data must match labels; cells must match cols
Symbols in numeric values changeListWidget values are numbers only; displayType handles formatting
Card used for a list Use messageListWidget for more than one item
Malformed badge cell Use {"type":"badge","text":"…","priority":"…"}
Invalid Sankey references Every source/target must be an existing node id
Vague display prompt Name the widget, the fields and the number of items

Multi-select table submit¶

Set properties.id, selectMode: "multiSelect", optional multiSelectActionText, and optional multiSelectMetadata. The app returns selected row objects under value[0].value, not a plain list of record IDs:

<oraFormSubmit id="selected_suppliers">
{"value":[{"id":"selectedRows","value":[{"cells":["SUP-1042","Acme Parts"]}]}],"metadata":{"purpose":"supplier_review"}}
</oraFormSubmit>

multiSelectMetadata becomes top-level metadata unchanged. Preserve stable identifiers in row data so the workflow can resolve the selection.
