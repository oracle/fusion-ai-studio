Test Agentic Apps with ATLAS¶

ATLAS — Agentic Testing and Lifecycle Automation Suite creates and runs source-controlled regression tests for Agentic Apps and their backing workflows. It combines replayable boundary data, deterministic assertions, semantic evaluation, and linked reports.

This page summarizes the app testing workflow. Tool commands and supported modes depend on your installed AI Studio tooling.

Cover workflows and panels¶

Test level What it verifies
Workflow Routing, transformations, data use, app stages, fallbacks, deterministic output, and answer quality
App panel The top-level panel's InitDisplay contract through the app runtime, including workflow wiring and widget structure

Complete backing workflow coverage before app panel tests. A panel test does not replace branch coverage. Shared workflows can serve different panels, so verify each panel's display instructions and discriminator.

ATLAS derives allowed widgets from the effective panel configuration: container startup override, matching panel widget list, then agent defaults. If absent, it checks the terminal workflow output specification. With neither source, it uses structural checks rather than inventing a widget requirement. An allowed pattern is not necessarily required.

Test handlers in the workflow tools¶

Before building a regression suite, isolate each handler in the workflow debugger or code playground using agentic-app test mode.

Check individual app stages¶

Select the mode for the stage you are implementing and supply representative $inputMessage, $OraAppContext, and $OraUserContext values. A successful Query run does not verify startup displays or action handling.

Stage or interaction Check
InitDisplay Display tags render; shared panels use their own $OraAppDisplayDiscriminator; any startup actions or communications are valid
Summary, InitTitle, InitSubtitle Return concise text for the requested purpose
InitActions, InitCommunications Return the stage's suggestions, including an empty result when none apply
Query Pass the current input and history; test a follow-up question
Action follow-up Run the configured step chain and inspect the command/content in $inputMessage and any supplied $OraAction
Form or editor submit Parse oraFormSubmit from $inputMessage; verify the form ID and expected payload shape
AdditionalContent Set $OraPanelName to each configured panel name
Starter queries and filters Test strict JSON separately from Query; include empty suggestions and an empty picker search

Some workflow tools label communications mode initComms; the runtime hint is still InitCommunications. For dynamic starters, select InitSampleQueries when available, or send an app-style request with that hint. For QueryFilterValues, provide Category ID and Search String. Use app Preview for the complete UI interaction after verifying the handler.

Start with a natural-language request¶

Use an AI coding assistant with the AI Studio tooling configured. Example requests:

Show me the app test sync plan for Supplier Risk Workspace.
Include backing workflow coverage. Do not create or run tests.

Generate and run tests for Supplier Risk Workspace and all backing workflows.
Complete workflow coverage first, then validate every testable top-level panel.
Complete semantic judging and show the consolidated results and caveats.

A sync plan previews missing, changed, and unmatched scenarios. Executing the plan prepares data, creates or updates tests, runs them, completes judging, and updates reports. Custom tests retain user-owned intent; unmatched or deleted-path tests are flagged for review rather than automatically deleted.

Data and assertions¶

Capture or generate representative responses at supported external-data and workflow boundaries. Replay those responses while letting conditions, code, transformations, and model nodes execute. This makes regression runs portable across compatible environments. It does not verify the current live integration, which needs a separate live check.

Use exact checks for stable routes, schemas, deterministic values, execution counts, and budgets. Use semantic judge criteria for grounded reasoning, completeness, and flexible prose. Do not freeze incidental LLM wording into exact assertions. For sensitive recorded data, use a reusable masking profile that preserves related identifiers consistently.

For app coverage, include empty data, missing inputs, shared-panel routing, Query follow-ups, communications, artifact edits, and the additional hints enabled by the app. App panel sync focuses on top-level InitDisplay; other interactions need workflow or custom coverage.

Read the results¶

Review consolidated, app suite, backing workflow suite, and individual test reports. Check failures, pending judgment, scenarios that could not be generated, unsupported claims, and links to evidence. A deterministic pass with outstanding semantic evaluation is incomplete. A passed with caveats report still requires review of its non-gating failures or unsupported claims.

Reports also expose duration, tokens, AI units, and optimization guidance. Compare models against the same replay data, and rerun the combined configuration before adopting an optimization. Repair the workflow, data, or assertion according to the actual fault; preserve the intended contract.
