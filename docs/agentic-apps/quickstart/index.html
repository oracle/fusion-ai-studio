Quickstart: Succession Readiness Workspace¶

Build a manager workspace for reviewing succession coverage, performance, retention risk, and compensation across a team. This walkthrough uses the Succession Readiness Workspace app and its supporting resources.

You'll assemble the app in the Agentic Application Builder, using the supplied advisor workflows. For a source-based development path, see Pro-Code Development and the repository's AI Studio skill.

Before you start¶

You need:

  • Access to AI Agent Studio and the Agentic Application Builder, with permission to configure workflows and apps.
  • The sample's workflows and Business Objects configured in your environment, including their referenced dependencies.
  • A manager test account with direct reports and representative succession, talent-rating, and compensation data accessible to that account.
  • The companion Person Succession Readiness Workspace and its analysis workflows if you want to test employee drill-down.

The .app file defines the app's composition and action chains. The backing workflows and Business Objects provide data retrieval, rendering, candidate suggestions, and succession-plan creation. See the sample's functional guide for those dependencies and flows.

What you'll build¶

The app is named Succession Readiness Workspace, and displays Succession Planning as its page title. It uses two columns with these panels, ordered from top to bottom:

Position First column Second column
Top Succession Overview Risk of Loss
Middle Top Performers Impact of Loss
Bottom Talent Needing Assistance Compensation Summary

Managers can review team coverage, inspect an employee, request successor candidates, and review a candidate before confirming a successor.

1. Prepare the advisor workflows¶

In AI Agent Studio, verify that these six workflows are available and have Expose to Agentic Apps enabled. The panel headings differ from some workflow names.

Panel heading Agent code Initial display
Succession Overview XX_SUCCESSION_OVERVIEW_ADVISOR Succession availability and readiness gaps as a messageListWidget
Top Performers XX_TOP_TALENT_ADVISOR Strong performers as a messageListWidget
Talent Needing Assistance XX_BOTTOM_TALENT_ADVISOR Employees needing support as a messageListWidget
Risk of Loss XX_RISK_OF_LOSS_ADVISOR Retention ratings and scores as a multiRecordWidget
Impact of Loss XX_IMPACT_OF_LOSS_ADVISOR Business-impact ratings and scores as a multiRecordWidget
Compensation Summary XX_COMPENSATION_ADVISOR Salary, quartile, and quintile as a multiRecordWidget

Use the supplied workflows' App Experience settings and rendering instructions. For example, the overview workflow retrieves manager and direct-report context before routing on $context.$app.$OraMessageHint. Its separate routes handle initial display, summary, actions, queries, additional content, actions invoked by the user, and subtitle generation.

Confirm that calls to supporting workflows resolve, including XX_SUCCESSION_OVERVIEW_AGENT_TEAM, XX_FETCH_PERFORMERS, XX_FETCH_COMPENSATION_DETAILS, and XX_POTENTIAL_SUCCESSION_CANDIDATES.

→ Details: Configure Agents and Message Hints.

2. Create the app and arrange its panels¶

  1. Open AI Agent Studio › Applications, create Succession Readiness Workspace, and choose Start from scratch.
  2. In App Settings, set Title to Succession Planning. Leave the static Subtitle empty.
  3. Select a two-column layout under Page Options.
  4. Add six agent slots, select the advisor codes from step 1, and arrange them in the order shown above. Use the panel headings in the table as the section titles.
  5. On each advisor, enable Include in actions?, leave Include in summary? and Include in Communications? off, and enable Use draft workflow while developing while iterating.

The source app relies on the workflows' display instructions; it doesn't define panel-specific display prompts or widget overrides.

→ Details: Using the Builder UI.

3. Set the summary and additional views¶

Assign Succession Overview Advisor to the static Summary container. Leave the app-level Summary Prompt empty to use the workflow's instructions. Its summary highlights direct reports with no succession plan or no ready-now successor. The source has no custom Ask Oracle agent, so questions use the app's default routing.

On the Succession Overview slot, open Panels › + Add Panel and configure the following additional views, all served by XX_SUCCESSION_OVERVIEW_ADVISOR:

Heading Panel name
Impact Of Loss impactOfLoss
Risk Of Loss riskOfLoss
Succession Information successionInformation

Keep the panel names same as above. These views use the AdditionalContent path and $context.$app.$OraPanelName in the XX_SUCCESSION_OVERVIEW_ADVISOR workflow.

→ Details: Builder panel configuration.

4. Configure the app actions¶

Open Browse app components › Actions. Reproduce the sample's six action chains, keeping their codes aligned with the ora.Invoke() calls emitted by the workflows.

Code Display name Ordered steps
appNavigate Navigate to App Navigate to App → XX_PERSON_SUCCESSION_READINESS_WORKSPACE, with Pass Payload to Context on
rowNavigate Row Action Keep Action Available in UI → Send Agent Command, passing the payload
successionCandidates Succession Candidates Send Agent Command, passing the payload
addSuccessor Add Successor Send Agent Command, passing the payload → Refresh Agents for XX_SUCCESSION_OVERVIEW_ADVISOR, including Also refresh priority actions and Also refresh summary
viewSuccessorDetails View Successor Details Send Agent Command, passing the payload
viewSuccessorInfo View Successor Info Send Agent Command, passing the payload

rowNavigate sends work back to the originating advisor. appNavigate opens the separate person workspace. Their payloads serve different paths: the overview's action handler reads a command and data from $context.$app.$OraAction, while app navigation passes context to the destination's $context.$app.$OraAppContext.

For employee navigation, preserve the selected employee's pId and aId and the manager's managerPId and managerAId. Use values returned by the workflows. For candidate review and successor creation, preserve the action-specific payload generated by the supplied workflow; those paths need more than the navigation identifiers.

→ Details: Actions and App Context.

5. Connect employee drill-down¶

Make XX_PERSON_SUCCESSION_READINESS_WORKSPACE available as the target of appNavigate. Its four panels use these workflows:

  • XX_SUCCESSION_ANALYSIS for consolidated employee succession information.
  • XX_RISK_OF_LOSS_ANALYSIS for the employee's retention-risk view.
  • XX_IMPACT_OF_LOSS_ANALYSIS for the employee's business-impact view.
  • XX_COMPENSATION_ANALYSIS for the salary-history chart.

Open an employee from a parent panel and verify that all four views use the selected employee's context. Configure access to the companion app and its backing data for your test manager.

6. Preview the manager journey¶

Click Run app preview and check the following with your manager test account:

  • All six panels display the manager's direct reports and handle missing data clearly.
  • Succession Overview distinguishes missing plans from plans with no ready-now successor, and its summary reflects those gaps.
  • The overview's three additional views open and return the expected content.
  • A review action opens employee details; where offered, Suggest Successor returns candidates that can be reviewed.
  • Employee navigation opens the person workspace with the correct succession, risk, impact, and salary-history views.
  • Ask Oracle responds to questions such as "Which of my direct reports have no succession plan?" and "Show compensation details for my team."
  • In a test environment, confirming a successor completes the backing creation flow and refreshes the overview, priority actions, and summary.

The addSuccessor chain invokes a workflow that creates succession-plan data. Use a designated test employee and inspect the resulting records when verifying that path.

→ Details: Testing with ATLAS and Troubleshooting.

7. Publish¶

Publish the backing workflows through AI Agent Studio, including the dependencies used by the person workspace. Verify that their published versions contain the changes exercised in Preview: Use draft workflow while developing applies to developer mode, while end users use published workflows.

Publish the companion app for employee navigation, then publish Succession Readiness Workspace. Open the published workspace as a manager with the configured roles and repeat the display, query, and drill-down checks.

Next steps¶

  • Explore widgets for other ways to present readiness and compensation data.
  • Add communications if your use case needs manager outreach or review documents.
  • Read Best Practices before extending the sample for production.
