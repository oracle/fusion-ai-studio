Message Hints Reference¶

In one session, a single agent might write the summary line, render a chart, suggest actions, answer a question and draft an email. The message hint tells the agent which of those jobs a request is for.

Every time the app calls an agent, the framework sets:

$context.$app.$OraMessageHint

You can read it in an expression as {{ $context.$app.$OraMessageHint }}, or in a Code node as $context.$app.$OraMessageHint.

Three rules

  1. The framework decides which hint fires. Your code never triggers hints.
  2. Your job is to recognize the hint and respond with the right content for each hint you handle.
  3. One agent handles many hints. Use one workflow with a Switch node, not one agent per behavior.

Message hint values¶

Standard initialization hints (depending on configuration)¶

Hint The app is asking for Return Sent to
InitTitle Dynamic title A title The Dynamic Title and Subtitle Agent
InitSubtitle Dynamic subtitle or session tagline A short, personalized line The Dynamic Title and Subtitle Agent
Summary This agent's contribution to the summary 1–2 sentence overview Agents with Include in Summary (or the Summary agent)
InitDisplay Initial information displays One or more <oraInfoDisplay> blocks (may include actions/comms) All domain agents
InitActions Priority actions Zero or more <oraInsight> blocks Agents with Include in Actions
InitCommunications Suggested communications Zero or more <oraComms> / app-defined suggestions Agents with Include in Communications

Interactive hints (fire on user activity)¶

Hint Fires when Context delivered Return
Query The user asks something in Ask Oracle $context.$system.$inputMessage, $context.$system.$chatHistory An answer, optionally with displays, actions and comms
InvokeAction An action step sends work to an agent $context.$system.$inputMessage; $context.$app.$OraAction where supplied by the action path The result of executing the action
FillParameters A communication needs parameters Parameters-to-fill array The parameter values
SendCommunication The user confirms sending $context.$app.$OraCommNonTemplateParamList Send or complete the communication
AdditionalContent The user opens an additional panel $context.$app.$OraPanelName Content for that panel

Routing pattern¶

Switch node logic (pseudocode)
switch ($context.$app.$OraMessageHint):
  "Summary"            -> summary node
  "InitTitle"          -> title node
  "InitSubtitle"       -> subtitle node        (use $OraUserContext.fullName)
  "InitDisplay"        -> initial display node
  "InitActions"        -> actions node
  "InitCommunications" -> communications node
  "Query"              -> query node           (pass $inputMessage + $chatHistory)
  "InvokeAction"       -> action handler       (read $inputMessage and action context)
  "FillParameters"     -> parameter filler
  "SendCommunication"  -> sender               (use $OraCommNonTemplateParamList)
  "AdditionalContent"  -> panel router         (branch on $OraPanelName)
  default              -> query node

In a multi-agent app, the orchestrator first decides which agent gets a request (using agent descriptions). That agent's workflow then decides what to do based on the hint.

Which hints should your agent handle?¶

If you want… Handle
A headline or status line at the top Summary (and InitSubtitle for the tagline)
Charts, cards or tables on first load InitDisplay (and select widgets)
Suggested next steps InitActions and InvokeAction
Free-form questions Query (with a specific agent description)
Drafted messages InitCommunications, FillParameters, SendCommunication
Expandable detail panels AdditionalContent, branching on $OraPanelName

Close-up: InitDisplay + InitActions¶

These two hints build the first screen. Both follow the same pattern: enable the feature on the agent, write a specific prompt, and return well-formed output.

InitDisplay

  1. Turn on Expose to Agentic Apps. This adds the App Experience section.
  2. Under Select the widgets you want to use, choose at least one widget. Selecting widgets turns on displays, and limiting the selection stops unwanted widget types.
  3. Write a specific Display prompt, e.g. "Top 5 critical items as a Message List."

InitActions

  1. Enable Actions for the widgets in the App Experience section.
  2. Include in actions? with an Initial Actions Prompt in the Agent Editor.
  3. Make the workflow's InitActions branch emit <oraInsight> blocks whose followUpCommand is usually ora.Invoke(...).

When the selected action includes a Send Agent Command step, handle the resulting InvokeAction request. Read the forwarded command or payload from $inputMessage and the action context supplied by that path. Navigation-only and refresh-only actions run their configured steps without an agent handler. See Receiving action commands.

Things to remember¶

  • Don't try to trigger hints. Recognize them and respond.
  • Use one workflow with one Switch on $OraMessageHint.
  • For Query, pass the input message and chat history yourself.
  • Expose the agent and select widgets, or it won't appear in the Builder.
  • Write specific agent descriptions, because routing depends on them.
  • Spend the most care on InitDisplay and InitActions.

Additional feature-specific hints¶

Hint Trigger and inputs Return or behavior
InitContextSuggestions Context switcher opens; $OraRequestDefaultAppContext indicates whether a default may be returned Default {name, appContext} object only when requested, otherwise a message-list display of context choices
QueryContextSuggestions Context search; read $context.$system.$inputMessage Message-list display of matching contexts; empty list for no results
InitSampleQueries Dynamic starter queries at initial load and on app-context changes Strict JSON category map with displayName and samples; {} if none
QueryFilterValues Ask Oracle value picker opens or search changes; read $OraQueryFilter JSON array of strings or {name, metadata} objects
InvokeCapability Autonomous capability call through an app Route on stored capability name in $OraAction; consume $OraActionPayload

These paths are separate from ordinary Query handling. InitSampleQueries and QueryFilterValues return JSON rather than widget tags or explanatory prose. See Ask Oracle, App Context, and Autonomous Outcomes.

For InitDisplay, use $OraAppDisplayDiscriminator to distinguish shared-workflow startup panels. Continue using $OraPanelName for AdditionalContent. Startup displays can also include actions and communications.

In workflow test tools, a mode labeled initComms still delivers InitCommunications as the hint. Use agentic-app run profiles and supply realistic app/user context. Use InitSampleQueries where listed, or an app-style request with that hint if the tool version lacks the selector.
